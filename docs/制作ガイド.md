# 動画制作ガイド (大元ルール)

このリポジトリで動画を作るときの全体のやり方と、これまでに決めたこだわりを全部まとめた文書。
**新しい作業セッションでは、最初に「docs/制作ガイド.md を読んで」と伝えればここの内容が前提になる。**
ルールを変えたいときは、コードと一緒に必ずこのファイルも更新する (ここが大元)。

---

## 1. 全体像

台本 (ただのテキスト) を渡すと、以下が全自動で走ってMP4ができる。

```
台本 → 1文=1シーンに分割 → Claudeが絵を割り当て (絵づけ)
     → 機械的な比率補正 → VOICEVOXでナレーション合成
     → scenes-data.json → Remotionで描画 → video.mp4
```

- リポジトリ: https://github.com/yousunafu/movie (ローカル: `~/Desktop/1005/movie`)
- 実行: GitHub Actions の「動画を生成」ワークフロー
- 操作手順の詳細は `README.md`、台本の書き方も `README.md` を参照

### 題材と作風の相性 (上司フィードバック 2026-10) ★重要

- **暗い色調** (ashi / manabi) は「心理・社会・群衆の構造」や「宇宙・深い時間・研究の歴史」などスケールの大きい題材向き
- 物理・科学は**身近な例より宇宙・研究史などの大ネタ** (インテリ層の高齢者向け・広告単価高)
- 「身近な物理 × 暗色図解」は相性が微妙 (実例: 金属がヒヤッとする話)

## 3. 動画を作る手順 (通常ルート)

1. GitHub → **Actions** → 「動画を生成」→ **Run workflow**
2. 入力:
   - `gist_url` = GistのRaw URL **またはリポジトリ内パス** (例: `docs/ashi-sample-script.txt`)
   - `preset` = `genki` / `ashi` / `manabi` / `rekishi` / `kouzou` / `keizai`
3. 完了後の受け取り (コマンドで):
   ```
   gh run list --repo yousunafu/movie
   gh run download <run-id> --repo yousunafu/movie
   ```
   video.mp4 をデスクトップの `out/` に**日本語名**でコピーして納品する。

## 4. ashi の演出ルール (v1 / v2 の混在) ★重要なこだわり

派手なv2演出は**一部のシーンだけ**。残りは落ち着いたv1。ユーザー確定ルール (2026-10)。
実装: `src/remotion/Video.tsx` の `ashiV2Indices()` + `AshiV2Context`。

**v2演出を使うのはこの3種類だけ:**

| 対象 | 演出 |
|---|---|
| 最初の行列シーン (character + motif=queue、**1回だけ**) | ミニストーリーアニメ (お店→密な行列→一人が歩いてきて「!」) |
| チャートシーン全部 | 100人グリッド点灯 + カウントアップ |
| 最初のカード (結論カード以外、1回だけ) | 文字ドン (「」引用→強調語が大きく出る) |

**v2のシーンにだけ付くもの:** ズーム・暗転フェード (AshiMotion)、光の粒 (Particles)、街灯のゆらぎ、字幕の黄色強調 (`#FFD966`)。

**それ以外は全部v1:** 金の額縁カード、静かな行列の絵 (2回目以降のqueue)、ズームなし、白い明朝体字幕 (黄色強調なし)。

このルールは**シーン番号ではなく種類で判定**しているので、新しい台本でも自動で同じ見た目になる。

## 5. manabi の演出ルール (図解が主役) ★重要なこだわり

お手本 (学びたい大人のための大学) の分析から決めた「わかりやすさを生む動き」。実装: `src/remotion/manabi/ManabiScenes.tsx`。

- **図解が主役**なので、genki用の人物比率などの機械的補正はかけない (`enforce.ts` はmanabiでは「最後は結論カード」だけ守る)
- **現象はその場で起きる**: 手がすっと伸びてドアノブに触れる → 青いヒヤッ記号と「!」/ 木に触れると温かいオレンジの輪
- **グラフは線が左から伸びる** (ナレーションと同期)。急降下する線がどちらかは項目の順番ではなく**言葉で判定** (金属・銅・タイルなど)
- **倍率はグリッド比較**: 「2000倍」→ 1マス (丸で囲んで見せる) vs 同じ大きさのマス2000個の壁 + 「約2,000倍」カウントアップ
  - マスの大きさは倍率に合わせて**自動で縮小** (最小3px、左の1マスも同じ大きさ)。「約10,000倍」でも1画面に正直に収まる。小ささ自体がスケール感の演出になる
- **矢印は順番に流れる** (熱の移動など)。粒の列は熱が左から順に伝わって光る
- 熱の流れ図は、受け手が木などの「奪わない物」なら矢印をほとんど流さない (意味が逆にならないように言葉で判定)
- 絵の選択は **type より motif (題材) を優先** (AIが type を diagram/object で揺らしても専用の絵が出る)
- 題材セットは2テーマ分: **熱の話** (touch_metal / heatflow / molecules / graph など) と **人類の痕跡** (city / ruin / decay / dinosaur / fossilize / strata / future_fossil / moon_footprint)。
  痕跡系はmotif名のゆらぎも吸収する ("rust"→decay、"moon"/"footprint"→moon_footprint、"fossil"→fossilize など。実装: ManabiScenes.tsx の resolveTraceMotif)
- **5分尺対応の追加モチーフ3種** (2026-10、台本見本: `docs/jinrui-konseki-5min-script.txt` 55文):
  - flood: 都市の断面図。地下鉄のトンネルに水位が静かに上がる (水没・地下鉄・ポンプの文)。ゆらぎ: subway / metro / submerge も flood に解決
  - trash_layer: ゴミ処分場の断面。層が下から積み重なり、ボトル・鶏の骨・陶器をオレンジの輪で順にハイライト (処分場・ゴミ・考古学者の文)。ゆらぎ: trash / landfill / garbage / waste
  - timeline: 数十年→数百年→数千年→1万年の年表。左から軸が伸び、目盛りと注釈が順に現れる (最後の目盛りだけオレンジ)。注釈は items の label で差し替え可
  - 「緑が都市を覆う」は新モチーフにせず既存 ruin で表現 (overgrow も ruin に解決)
- **章扉カード** (5分尺対応): 「まず」「ここからは」「最後に」等で始まり「第1章」などの章番号を宣言する文は **type: card, motif: chapter**。
  濃紺背景にオレンジの細線 + 章番号 (オレンジ・明朝) + 章タイトル (白・明朝) が**静かに1秒でフェードイン**。
  章タイトルは title から取り (章番号は除去)、無ければ本文から前置き・結び (「〜から見ていきましょう」「〜の話です」等) を削って自動抽出。
  章扉カードには字幕を重ねない。AIが type を揺らしても enforce が「第N章」を含む文を card+chapter にそろえる
  (= manabi の enforce は「最終結論カード + 章扉カード」を守る)
- カード (章見出し・結論) は明朝体で、**キーワードだけオレンジ**。カードが全文を見せるときは字幕を重ねない (二重表示防止)
- 画面左上に小さく「— チャンネル名」のヘッダー
- 台本のコツ: 「〜は…の2000倍」のような**数字の文**、「なぜ〜でしょうか」の**問いの文**、「答えは〜」「〜とは、…なのです」の**結論の文**を入れると、チャート・問いかけ・カードが自動で入る

## 6. rekishi の演出ルール (資料図版が主役) ★重要なこだわり

お手本 (世界史裏探訪) の「資料画像スライド + 黒帯字幕」を、AI画像休止中のため**セピアの銅版画調SVG**で再現。実装: `src/remotion/rekishi/RekishiScenes.tsx`。

- レイアウトは全シーン共通で **上8割 = 図版 / 下2割 = 真っ黒の帯**。字幕は黒帯の中央に白ゴシックで全文1〜2行
- **銅版画調**: 細い平行ハッチングで陰影 + 絵の周囲に二重の額装枠 + ゆっくりKen Burnsズーム (1.0→1.06。chartだけ数字がぶれないようズームなし) で「資料スライド」感を出す
- 図版の下に「Fig. N ─ ◯◯」の博物図版風キャプション (明朝)
- **カードは紙白の全面スライド**: items があれば見出し + **箇条書き** (・は錆朱、1行ずつ順に出る)、emphasis の語だけ錆朱。カードが全文を見せるときは字幕を重ねない (`rekishiCardShowsFullText`)
- 倍率グリッド比較・motif優先ルーティング・言葉での意味判定・enforce最小限 (結論カードだけ) は manabi と同じ共通原則

## 7. kouzou の演出ルール (構造の図解が主役) ★重要なこだわり

お手本 (Motocrab 世界構造考察) の「生成り背景 + 黒ピクトグラム + 図解」を再現。実装: `src/remotion/kouzou/KouzouScenes.tsx`。

- レイアウトは全シーン共通で **上 = 生成りの紙の図解 / 下端 = 黒帯 (150px)**。字幕は黒帯の中央に白ゴシックで全文 (rekishi より薄い帯なのでフォントも少し小さめ)
- **色は3つだけ**: 黒〜墨のピクトグラム・線・矢印 / 差し色の青緑1色 / 章・結論カードだけ濃紺に白文字 (emphasis の語だけ青緑)。画面左上に小さく「— チャンネル名」
- **演出は静かで知的**: 線が描かれていく・矢印が伸びる・分岐の箱が順に現れる・吹き出しが増えていく。全部ナレーションと同期して順番に動く (manabi で実証済みの原則)
- 題材セット (KOUZOU_MOTIFS): meeting (会議室、吹き出しが増える) / structure (箱3つの分岐図、青緑で順に点灯) / mix (報告・議論・決定が1つの枠に押し込まれる) / no_end (チェックボックスに×、時間の線が伸び続ける) / silence (沈黙→不安→発言の連鎖の矢印図) / anchor (60分のバーに錨、30分で結論が出ても60分まで埋まる) / law (枠=与えられた時間、中身が枠いっぱいに膨らむ) / concept (汎用のネットワーク図。想定外motifの受け皿)
- **カードは章の切り替えと最後の結論だけ** (enforce.ts が本編のカードを図解に戻す。章の文かどうかは `isKouzouChapterText` = 「次に、〜です。」のような短い文で判定)
- 絵の選択は **type より motif を優先** + motif名のゆらぎは `resolveKouzouMotif` で吸収 ("meeting_room"→meeting、"boxes"→structure、"parkinson"→law など)
- chart は棒バー比較 (30分 vs 60分) + カウントアップ。本文で言及された数字の側を青緑で強調
- カードが全文を見せるときは字幕を重ねない (`kouzouCardShowsFullText`)

## 7-2. keizai の演出ルール (ニュースフリップが主役) ★重要なこだわり

お手本 (大人の学び直しTV) の「ニュース番組のフリップボード解説」を再現。実装: `src/remotion/keizai/KeizaiScenes.tsx`。

- **画面の骨格は全シーン共通**: 濃紺のスタジオ風グラデ背景 (`#0B1430`→`#16254D`、上からの照明と床の影) + 右上に小さな番組名リボン (赤タブ+白箱)。その上に**白いフリップボード**がスッと差し込まれる (spring、約0.5秒)
- **フリップの型**: 上部に**赤い見出しバー** (白太字) + 本文は紺のゴシック。大事な数字は**黄色の特大文字** (`#FFD400`、紺の縁取り) でドンと見せる
- **順に点灯**: 複数の箱 (仕入れ値→企業→価格転嫁 など) は、ナレーションに合わせて約1.1秒おきに1枚ずつ明るくなる (待ちの箱は透明度を落として置いておく)
- 題材ごとの専用フリップ (motif):
  - `news` = 速報風の見出しテロップ (導入。「」内を見出しに抜き出す)
  - `exchange` = 両替の図。1ドル=100円→150円 の**カウントアップ** (items の2つの数字を使う)
  - `import_japan` = 日本地図の簡略形+外から入る黄色矢印+「食料 約6割」などの赤バーフリップ
  - `cost_chain` = 仕入れ値→企業→価格転嫁の矢印チェーン (順に点灯)
  - `ripple` = 小麦→パン、原油→電気代・輸送費の分岐図 (線が描かれてから先端に矢印)
  - `transport` = トラックのピクト+値札3枚に黄色の「輸送費」層
  - `price_up` = 値札の数字が上がるカウントアップ+赤い上向き矢印
  - `balance` = 天秤。左に痛み (赤)・右に恩恵 (緑)。springで傾いて落ち着く
- **チャートは横棒**: 緑 `#3BA55C`・紫 `#7B5EA7` の横棒が左から伸び、値は棒の中に白文字。本文で言及された数字 (なければ最大値) だけ黄色の特大数字を添える
- カード (結論) は白フリップ全面: items があれば赤い■の箇条書きが1行ずつ、なければ全文を大きく (emphasis の語だけ赤)。カードが全文を見せるときは字幕を重ねない (`keizaiCardShowsFullText`)
- 絵の選択は **type より motif を優先** (card/chart を除く)。motif名のゆらぎは `resolveKeizaiMotif` が吸収 ("dollar"/"rate"→exchange、"truck"→transport など)
- enforce はmanabi/rekishiと同じく最小限 (最後の実質シーンを結論カードにするだけ)
- 台本のコツ: 「1ドル=100円が150円になった」のような**数字の変化の文**、「仕入れ値→価格に転嫁」の**連鎖の文**、「つまり〜なのです」の**結論の文**を入れると、両替図・矢印チェーン・まとめフリップが自動で入る

## 8. チャートのルール

- パーセントの値は**100人の人型グリッド**で表現: 4% → 100人中4人が点灯。点灯数はカウントアップと同期
- **強調 (大きく・琥珀色) するのは本文で言及された数字**の側 (例:「4パーセントでした」→ 4%側)。言及がなければ最大値
- AIが value を文字列 (「4%」など) で返しても `coerceItem` (src/generator/assign.ts) が数値化する

## 9. 字幕のルール

- 日本語の文節で折り返す (budoux)。「たんぱ/く質」のような変な改行をしない
- genki: 濃いグレー太字・帯なし / ashi: 白い明朝体+影、AI画像の上では暗い帯 / rekishi: 下2割の黒帯の中に白ゴシック全文 / kouzou: 下端の黒帯 (150px) の中に白ゴシック全文 / keizai: 画面下部に白ゴシック太字+黒の縁取り (ニュースのテロップ風。帯なし)
- ashi v2シーンだけ、強調語 (emphasis) を黄色にする

## 9-2. カード・大事な言葉の改行ルール (全作風共通) ★kouzou指摘で確立

結論カード・まとめフリップ・箇条書き・文字ドンなど「まとめや大事な言葉を大きく見せる画面」の折り返しも、字幕と同じく**文節単位 (budoux)** で行う。

- 共通ヘルパー **`src/remotion/wrapJa.tsx` の `wrapJa(text, hl?, hlStyle?)`** を使う (全作風がこれを呼ぶ)
- 強調語 (emphasis) は**「」ごとひとかたまり**にして、途中で絶対に割れない (例:「今日決めること」が「今日決め/ること」にならない)
- 強調色は hlStyle で作風ごとに渡す: kouzou=青緑(明るめ) / manabi=オレンジ / rekishi=錆朱 / keizai=赤
- **文章を短くするのではなく、改行位置で見栄えを整える**のが方針 (ユーザー確定 2026-10)
- 新しい作風を作るとき (§13) も、全文を見せるカードや箇条書きには最初から wrapJa を使うこと
- このルールは次作から適用。既納品の動画はそのまま (作り直さない)

## 9-3. レイアウト検品ルール (全作風共通の制作方針) ★2026-10 ユーザー確定

動画を作るとき・直すときは、絵づくりの段階から次の4点に気を配り、**納品前に静止画で必ず検品する**。
既存作風のコードは現状キープでよい (問題が見つかった作品だけ直す)。次に作る作風・画面には最初から組み込む。

1. **イラスト・図と文字を重ねない**: 図解やピクトグラムがタイトル・ラベル・字幕 (帯) にかからない配置にする (例: kouzouのmix矢印がタイトルに刺さっていた失敗)。画面下部は字幕が来る前提でレイアウトする
2. **文字を枠からはみ出させない**: 箱・カード・フリップの中の文字は、文字数に応じて**枠の幅を自動調整**するか文字を縮める (例: kouzou構造図の `boxWs = 文字数×40+90`)。固定幅の枠に長文を入れない
3. **タイトルの下線は文字幅に連動**させる (例: kouzou `SheetTitle` の `uw = 文字数×フォントサイズ×0.96`)。※カード上下の短いアクセント線 (飾りの区切り線) は対象外
4. **改行は文節単位**: 下の字幕は全作風とも共通字幕 (Video.tsx の Subtitle) がbudouxで文節改行済み。カード・まとめは §9-2 の wrapJa を使う

検品のやり方: 納品前に各シーンの代表フレームを `npx remotion still` で書き出し、「重なり・はみ出し・下線幅・改行位置」の4点を目視チェックしてから納品する (§13 の手順5と同じ要領)。

## 10-1. 声の緩急 (長尺対策) ★2026-10 導入

20分聴いても単調にならないよう、文の種類で話し方を自動で変える。実装: `src/generator/pacing.ts` (VOICEVOXのみ)。
**字幕は原文のまま**、読み上げだけ変わる。

| 文の種類 (言葉で自動判定) | 話し方 |
|---|---|
| 問いかけ (「〜か。」で終わる) | 少しゆっくり・抑揚強め・文末に0.5秒の「考える間」 |
| 章扉カード (card + chapter) | 少しゆっくり・前0.4秒/後0.7秒の間 (場面転換の呼吸) |
| 結論カード・締めの挨拶 | 少しゆっくり・文末0.5秒の余韻 |
| 通常の文 | 従来通り (話速0.95・文末0.15秒) |

- 「答えは」「つまり」「実は」「ところが」「なんと」の直後に読点を足して**タメ**を作る (`ttsTextFor`。字幕には出ない)
- 生成ログのシーン行に (問いかけ) (章扉・間) (結論・余韻) のラベルが付くので、判定の確認ができる
- 数値を調整したいときは `pacing.ts` の1か所だけ直す

## 11. Actionsを回さずに作り直す技 (ローカル再納品)

絵や演出だけ直すとき、ナレーションが同じなら Actions 不要。約10分で再納品できる。

1. 過去の run をダウンロード → `scenes-data.json` を取り出す
2. 全シーンの `audio` を無音wavに差し替え (`ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t 0.5` で作る)
3. 直したいシーンのデータ (motif / emphasis / 数値など) を編集
4. `npx remotion render src/remotion/index.ts Main out/render.mp4`
5. 元のmp4から音声を移植:
   ```
   ffmpeg -i render.mp4 -i 元の動画.mp4 -map 0:v -map 1:a -c copy 完成.mp4
   ```
   ※ durationSec が同じならフレーム数が一致するので音ズレしない

## 12. 作業の作法 (セッション内ルール)

- シーンの指定は**ユーザーは1始まり** (1枚目 = index 0)。番号付きの一覧画像を出すと話が早い
- テストは `scenes-data.json` を書き換えて `npx remotion still` で静止画検証
  → **コミット前に必ず `git checkout -- src/remotion/scenes-data.json`**
- 変更の切り分け: **今後も使うルール → コードに実装してコミット** / その動画だけの修正 → データ編集 (コミットしない)
- コミットは日本語 (「修正:」「変更:」)。ルールを変えたら本ガイドも同時に更新
- ユーザーは非エンジニア。日本語で、ブラウザ操作は手順を細かく案内する

## 13. 新しい作風 (プリセット) を追加するときの手順 ★manabiで確立した型

manabi (2026-10) を作ったときの流れがうまくいったので、次に新しい作風を作るときもこの順でやる。

1. **お手本動画を分析**して「色・フォント・演出の核」を3〜5個に絞って決める (例: manabi = 濃紺・白線画・図解が主役)。決めたら本ガイドの §2 と専用セクションに書く
2. **専用フォルダにシーン描画を実装** (`src/remotion/<preset名>/`)。`Video.tsx` にプリセット分岐を追加
3. **わかりやすさの原則** (manabiで効果が実証済み。新作風でも流用する):
   - 現象はその場で起きる (手が伸びて触れる → その瞬間に記号が出る)
   - グラフ・矢印・点灯は**ナレーションと同期**して左から順に動く
   - 倍率の比較は**同じ大きさのマス**で正直に見せる (1マス vs N個の壁)。大きさをごまかさない
   - ラベルや数字は**字幕と重ならない位置**に置く (画面下部は字幕の帯が来る)
   - カード・箇条書きの折り返しは**文節単位** (§9-2 の `wrapJa` を最初から使う)
   - **レイアウト検品 (§9-3) を最初から組み込む**: 図と文字を重ねない / 枠は文字数で自動調整 / タイトル下線は文字幅に連動
4. **AIのブレ対策を最初から入れる**: 絵の選択は type より motif (題材) を優先 / 意味の分岐はシーン番号ではなく**言葉 (ラベルの中身) で判定** (例: 急降下する線は「金属・銅・タイル」側)
5. **テストは仮の scenes-data.json + `npx remotion still`** で静止画を量産して確認 → Actions は1回だけ回す
6. Actions の出力で気づいた修正は **§11 のローカル再納品**で直す (Actionsを回し直さない。約10分で済む)
7. 直したルールは**コード + 本ガイドに反映してコミット** (その動画だけの修正ならデータ編集のみ)
