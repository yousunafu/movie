# 作品カルテ (2段目ルール: 個別作品の修正事例と作者の好み)

1段目 = `docs/制作ガイド.md` §9-4 の全作風共通原則。このファイルはその**2段目**で、個別作品ごとに「どんな指摘を受けて → どう直して → そこから読み取れる作者の好みは何か」をタイトルごとに収納する。

## 使い方 (運用ルール)

- **新作を作る前に**: ガイド§9-4 を前提に、ここを**全作品ぶんザッと読む**。繰り返し出てくる指摘 = 作者が特に気にするポイントなので、新作では最初から織り込む
- **納品したら**: その作品で受けた指摘・直しの概要と「読み取れた好み」を、下の型で**必ず追記**する
- 書き方の型: タイトル見出し → 「指摘と直し」(箇条書き) → 「読み取れた好み」(1〜3行)。コードの詳細はガイド側に書き、ここは**概要とニュアンス**を残す場所

## 望月の歌・道長回 (suuri / 2026-10)

### 指摘と直し
- 「同じ絵の繰り返しで萎えた」→ 登場回数を variant として絵に渡し、2回目以降は姿が変わる仕組みに (絵が育つ。§9-4 原則1の元)

- 絵は文の言葉そのもの (「子が3人」なら3人描く) を求める。雰囲気絵で流すのを嫌う

## 寿司37%ルール回 (suuri・和紙モード / 2026-10)

### 指摘と直し
- 「考える人」の体が字幕に刺さった → 字幕セーフゾーン y>840 を数値で確定 (§9-3)
- ラベルが右に見切れた (「旅先のレストラン」) → ラベルは原則絵の真下に中央揃え (§9-3)
- オチ (「…ガリでした。」) が先に見えてしまう → ナレーションがオチを読む瞬間まで絵も字幕も隠す (splitPunchline + tailReveal。§9-4 原則の元ではなく §9-3 項目9の元)

- 和紙モードの色変換で後から色修正が多発 → 最初の1〜2モチーフで変換後の見え方を確認してから量産 (§9-4 原則5の元)

### 読み取れた好み
- オチ・ネタバレの管理に厳しい。「言う前に見せる」のは厳禁
- 絵と文の意味のチグハグ (気分のミスマッチ含む) にすぐ気づく
- 尺や同期のズレより先に、まず「意味が合っているか」を見る

- 人物絵の連続を嫌う。内容のある文には必ずその文専用の絵
- 色は「あると分かりやすい所」に先回りで置いてほしい。後出しの色直しにがっかりする
- 深さ・規模の表現は大げさなくらいでちょうどいい (浅い穴は「穴」に見えない)

- 1シーンだけの音声再合成は tmp/resynth-scene123.ts 方式 (全124本やり直さず対象だけ再合成して durationSec を実測更新) で数秒で済む (恋愛版ドレイク方程式 / suuri / 2026-10)

### 指摘と直し

### 読み取れた好み
- テーマに合わせた空気づくり (恋愛=ピンク導入) を喜ぶ。作風固定ではなく題材に寄せる柔軟さを求める
- 「同じ図が別物に見える」のを嫌う。グラフ・式は前のシーンと連続して育ってほしい
- 検品は静止画→実映像の2段構え+再生成前のユーザー確認ゲートが定着。勝手に再生成しないこと

### 第二回修正 (v3・26項目) の事例と教訓 (2026-10-16 納品)
- v2への指摘26項目を反映して納品。主な改修: 東京ドームを「6個並び→1大ドーム拡大→好きだー!吹き出し」の3段ズーム構成に / 式の係数を全部「1/n」の分数表記に統一 / 宇宙人vs26人は天秤→不等号図の2段構成 / サイコロは当たり目 (1) だけ赤 / バッカス続報は回想3連 (学者→26人回想枠→論文の結びに虫めがね) で引っぱってから結婚を明かす
- **エンディング重複の罠**: channel.ts の closingLine (「最後までご覧いただき〜」) が自動付与されるので、台本側に「ご視聴〜」を書くと二重になる。台本には書かないこと
- **最終シーンは enforce.ts で必ず結論カード化される**。オチを図解で見せたいときは台本のオチを2文に割り、図解を「最後から2番目」に置く (今回: 「分母を増やせば。」=yurumeru図解 →「きっと出会えるはずです。」=結論カード)
- **assign.ts の新ルールは先行ルールに飲まれる**。追加前に同じ語句が既存ルールに拾われないか grep で確認 (今回「出会う数という分母」がまとめルールに飲まれ、「出会いの分母」に言い換えて回避)
- 黒モードの SP.ink は白 (#F2F2F4)。白地の部品 (サイコロの目など) には使えないので黒 (#26262B) を直接指定する
- タイトル帯 (上部) との被りも検品対象。吹き出しの上端は y≥160 を目安に (今回054で吹き出し2つがタイトルに被り、検品ユーザー指摘で発見)
- 字幕と同文の下部ラベルは、余白がなければ消してよい (情報が重複しているため)
- variant は computeSuuriVariants で「同一motifの通し登場回数」。台本に行を足すと後続の同motifシーンの variant が自動で進む (連続していなくてもよい) — オチ追加で yurumeru v2 が自然に割り当たった

### 第三回修正 (v4・読み間違い4件) の事例と教訓 (2026-10-16 納品)
- VOICEVOX読み間違い4件を TTS_READINGS (pacing.ts) に4行追加で修正: いい人→いいひと / 口にする→くちにする / 年に10人→ねんに10人 / ピーター・バッカス→中黒除去で一息読み
- **人名の「・」は読みが途切れる**。読み上げ側だけ中黒を除去すれば字幕はそのままで直る (カッコ外しと同じ発想)
- **「人」の「じん/ひと」誤読は頻発** (キラキラ回でも発生)。台本に「〜人 (ひと)」が出てきたら納品前に読みを疑うこと
- 置換の誤爆確認は台本grepで。「年に」は行28「1年に」(正読) があったので「年に10人」に限定置換した
- 音声だけの修正は絵が変わらないので静止画検品は不要。該当シーンをffmpegでクリップに切り出してユーザーに耳で確認してもらう方式が早い

### 読み取れた好み (v4)
- 読み間違いにも敏感。固有名詞の途切れ・「人」の読み分けは特に気にする。次作からは生成後の音声検品で「人」「年」「口」などの多読み漢字を重点チェック

### 第四回修正 (v5・10項目) の事例と教訓 (2026-10-23 納品)
- 字幕改行5件 (「行動できる人は、」「集まる街で、」「手に入れ、」「性質を知り、」「調律の頻度、」の直後) を Video.tsx の SUBTITLE_BREAK_AFTER に追加
- サイコロ2の目を黒点に / 天秤の傾きを逆に (1万個側が下がる) / 見出し「宇宙人の文明は1万個」(区切り記号なし) / 「1000万円」は TTS_READINGS で「いっせんまんえん」読み
- 新スライド追加: 「宇宙人を探す式が教えてくれたのは」→ 望遠鏡を覗くと鏡に自分が映る演出 (宇宙の広さに赤×、「映っていたのは、自分」ラベル)
- **suuriの共通文言は先行エピソード (nozoki) のルールに飲まれる**: suuriHeuristicAssign は全suuri回共通の1関数で、「今日の話を、まとめます」等が先に書かれたnozoki回のモチーフに取られた。再生成したら必ず生成ログ末尾のモチーフ一覧を照合し、他回のモチーフが混ざっていないか確認する。混入はコードを直さず scenes-data.json の直接パッチが早い (モチーフ変更だけなら音声再合成も不要)

- 再発防止3段構えを導入: ①台本1行目に「作風: suuri」宣言 (必須・無指定はエラー停止) ②環境変数PRESETと食い違ったらエラー ③生成後にモチーフ一覧をログ出力。詳細は docs/制作ガイド.md の「作風の指定ルール」

## 望月の歌・道長回 改訂版 (全面ビジュアルブラッシュアップ / suuri / 2026-10)

### 指摘と直し
- 「全体的に絵が地味。もっと豪華に」→ 平安貴族の世界観に合わせた**金 (#E8C34A) + 藤色 (#A58BD4) の専用パレット MC** を導入。章扉・系図・月・冠などの要所に金、藤原家まわりに藤色。赤は従来通り1画面1要素の強調専用
- 「地球儀のデザインが気に食わない。とくに謎の線。もっとちゃんとしたイラストに」→ 経緯線グリッドを全廃し、海の球体 + 見覚えのある大陸シルエット + 金の日本列島ハイライトで描き直し。**記号的な「それっぽい図」より、ちゃんと描いた絵**を求めている
- タイトル帯に吹き出しが被った → 吹き出し上端は y≥160 (運命の人回と同じ指摘の再発。帯の下端位置は数値で守る)
- 字幕被りが静止画検品で3件 → 修正後に再検品。**下部の要素は字幕セーフゾーンを最初から避けて置く**
- 本番レンダ後、実映像15フレーム抽出で最終検品 → 全合格で納品

### 進め方の教訓
- 道長レンダ中に覗き見君の音声を作る必要が発生 → public/audio は共有スロットなので触らず、**別フォルダ (out/nozoki-audio-new) に生成して後で差し替える方式で並行化**。レンダと音声生成は衝突しない
- 検品は「静止画で直す → 本番レンダ → 実映像フレーム再抽出で確認」の2段。実映像の時刻計算は durationSec+0.35 のフレーム切り上げ方式

### 読み取れた好み
- 題材の世界観に合った**色の豪華さ**を求める (平安=金と藤色のように、色選びに意味があると喜ぶ)
- 「謎の線」のような**説明のつかない要素**を嫌う。図形の飾り線より、意味のあるシルエットで描く
- 同じ指摘の再発 (タイトル帯被り) にはより厳しい。一度数値化したルールは全作風に横展開すること

### 追記 (2026-10-23)
- 納品後にユーザーから「道長にキラキラスマホ回のスライド入ってんじゃん」と指摘。assign.ts の汎用ルール (/第[1１一]章で/) がキラキラ回の章予告スライドを道長の予告文に割り当てていた → 道長専用の章予告スライド (mich_preview_ch12 / ch34) を新規作成し、assign.ts に先行ガードを追加して修正済み

- 教訓: **新エピソードの検品では「他エピソード専用モチーフの混入」を機械的にチェックする** (モチーフ名一覧を grep で照合)。15フレーム抽出だけでは章予告シーンを見逃した

### ★声が別人になる事故 (`PRESET` の取り違え)
- 音声を焼き直したら、一部のシーンだけ**ずんだもんではなく青山龍星**になっていた
