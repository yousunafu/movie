## 絶対に守ること

1. **1文 = 1シーン = 1枚の絵。**【N】文だから【N】枚。増やさない減らさない
2. **札 (TagPlate) の y + size*0.85 を 830 以下にする。** 画面の下には字幕の黒帯 (上端854) が別レイヤーで乗ります。検品プレビューには字幕が出ないので、目で見ても気づけません。必ず計算で守ること
3. **絵の中の文字は、ラベル・数値・標識だけ。** 台本の文章をそのまま絵に書かない (字幕が出るので二重になる)
4. **必ず `f` で何かが動く。** 静止した絵は禁止
5. **出そろうのは f=42 まで。** 検品プレビューは全シーンを f=45 の瞬間で描きます。`seg(f, a, b)` の b は 42 以下にすること
6. 色は `KRP` と `BP` にある色だけを使う。新しい色を足すなら、このファイル上部の `C` に足す
7. seed は 【S1】〜【S2】 を1シーンに1つずつ (もう骨組みに書いてあります。変えない)
8. 対応表 `SCENES` と `【MOTIFS配列名】` は**変えない**。部品名も motif 名も変えない

## 絵の「格」— これがこの章の肝です

| 格 | 中身 | 目安 |
|---|---|---|
| **山** | 舞台・人・事件・カメラ全部入り。全力 | 150〜250行 |
| **並** | 舞台はあるが、描くのは1つだけ。人は1人、背景3〜4要素 | 60〜120行 |
| **図** | クリーム地に図と札だけ。人も背景も置かない | 25〜50行 |

### ★「図」「並」も品質は落とさない (作者の指示そのまま)

> 「シンプルとか普通のやつも絵のクオリティは下げちゃだめなんだけどね。だけど、細かい作りこんだ絵が生きるのは、そのバランスがあってこそなんだよね」

短いのは**賑やかさを削ったから**であって、雑に描いたからではありません。

- 線・色・札・フォントは山と**完全に同じ**。`strokeWidth` を細くしない。ゆらぎフィルタ (`Frame`) を外さない
- **必ず動く。** 静止した図は禁止
- **図そのものを作り込む。** 滑車なら溝・軸・ボルト・ロープの撚りまで
- **大きく置いて画面を使い切る。** 最悪の失敗は「小さい物を画面の真ん中にポツンと置く」。シンプル＝小さい ではない。シンプル＝**1つを、大きく、正確に**。主役の装置は短辺で画面の1/2 (540px) 以上を使う
- 余白は「空っぽ」ではなく「寄り」。余白があるのは、そこに寄っているから

## 使える部品

`import` 行はもうファイルに書いてあります。主なものの使い方:

**`KosoShared.tsx` から**
- `<Frame f={f} seed={【S1】} bg={KRP.cream}>…</Frame>` — 手描きのゆらぎ。全シーンの外枠。必ず使う
- `<TagPlate x y text size t color fill />` — 木札。`t` は 0→1 で出てくる。幅 ≈ text.length*size+40
- `<QMark x y s t />` `<XMark x y s t />` `<Arrow x y s rot t />`
- `W`=1920 `H`=1080 `FONT`

**`KarakuriScenes` から**
- `<Person x y s ...>` — x,y は**足元**。頭のてっぺんは y - 292*s
- `seg(f, a, b)` → f が a〜b の間で 0→1 (範囲外は0か1) / `easeOut(t)` / `clamp01(x)` / `pop(t)`
- `KRP` — 共通の色 (ink, cream, white, red, green, orange, yellow, gray, grayDark …)

**`KosoB2Parts.tsx` から** (この章のために作った説明の装置。**使う前に該当箇所を Read して引数を確認すること**)
`BP` (鉄・真鍮・麻縄などの色) / `lerp` `rnd` `zoomAt` `bobOf` / `Rivets` `HexBolt` / `GridPaper` (図の方眼下地) / `Rope` (撚りまで描く綱) / `RopeFray` / `Sheave` (綱車。溝・スポーク・軸・ボルト) / `GrooveSection` (溝とロープの断面) / `GuideRail` `ToothRail` / `Spring` `Pawl` `Sparks` / `Car` (かご) / `Counterweight` (つり合いおもり) / `Shaft` (縦穴ぜんぶ) / `Balance` (てんびん) / `Maru` `MaruBatsu` / `SpeedGraph` / `FloorScale` / `ForceArrow` / `ButtonPanel` / `Lever` / `FlowPlates`

**`KosoPillars.tsx` から**: `KPP` (柱の色) / `TowerOnPillars` (5本柱の上にタワマン群)。【使う文番号】で使う

## 「図」の見本 (文#71。これと同じ作りこみ・同じ大きさで描く)

```tsx
const Kb2RopeKasshaHito: React.FC<{ f: number }> = ({ f }) => {
  const SX = 760, SY = 330, SR = 210;          // 綱車の中心と半径
  const LX = SX - SR * 0.82;                   // 荷台側
  const HX = SX + SR * 0.82;                   // 手側
  const pull = (Math.sin((f - 10) / 14) * 0.5 + 0.5) * easeOut(clamp01(seg(f, 4, 28)));
  const handY = 640 + pull * 130;
  const loadY = 790 - pull * 130;
  const rot = -pull * 44 + f * 0.6;
  return (
    <Frame f={f} seed={605} bg={KRP.cream}>
      <GridPaper />
      {/* 吊り元の梁。画面を端から端まで横切らせる */}
      <rect x={-20} y={66} width={W + 40} height={58} fill={BP.wood} stroke={KRP.ink} strokeWidth={7} />
      <Rivets x1={60} y1={95} x2={1860} y2={95} n={14} r={8} fill={BP.woodDark} />
      {/* ロープ: 荷台 → 綱車 → 手 */}
      <Rope x1={LX} y1={loadY - 58} x2={LX} y2={SY} w={22} kind="hemp" f={f} />
      <Rope x1={HX} y1={SY} x2={HX} y2={handY - 24} w={22} kind="hemp" f={f} />
      {/* 綱車。画面の高さの4割を使う */}
      <Sheave x={SX} y={SY} r={SR} rot={rot} spokes={6} groove bracket />
      {/* 荷台と樽 … 吊り鎖・板・樽2つ */}
      {/* 引く手。人は置かない。手だけに寄る … 腕・袖・掌・指4本・親指・握りの皺 */}
      <ForceArrow x={HX + 118} y={handY + 70} len={230} rot={90} w={24}
        color={KRP.red} t={seg(f, 14, 30)} label="引く" labelSize={36} />
      <ForceArrow x={LX - 268} y={loadY - 84} len={230} rot={-90} w={24}
        color={KRP.green} t={seg(f, 20, 36)} label="上がる" labelSize={36} />
      <TagPlate x={1450} y={330} text="滑車" size={56} t={seg(f, 6, 20)} />
      <TagPlate x={1450} y={450} text="溝にロープが乗る" size={32} t={seg(f, 16, 30)} />
      <TagPlate x={1546} y={790} text="人の力" size={46} t={seg(f, 26, 42)} color={KRP.red} />
      <TagPlate x={330} y={790} text="荷物" size={40} t={seg(f, 10, 24)} />
    </Frame>
  );
};
```

要点: **主役を大きく / 画面の端まで使う / 部品の内部まで描く / 矢印と札で意味を言う / 必ず f で動く**。

★この見本は**完成した1枚を丸ごと**貼る。「こういう感じで」と言葉で説明しても伝わらない。
★「図」の見本を貼るのがいちばん効く。「山」は放っておいても全力で描くが、「図」は手を抜かれやすい。

## 進め方

1. まず `【担当ファイル名】` を Read して骨組みを把握する。次に `KosoB2Parts.tsx` を Read して部品を把握する (この2つだけ最初に読む)
2. 骨組みの各シーンにある `// どこ: // 演出: // 動き:` のコメントを**先に埋めてから**描く
3. 【N】枚を**一気に書く**。Edit で `{/* TODO */}` を置き換えていく
4. 書けたら型チェック: `node_modules/.bin/tsc --noEmit`
5. 札の検査: `npx tsx scripts/koso-plate-check.ts 【担当ファイル名から .tsx を取った名前】` — **NG 0件になるまで直す**
6. 静止画を書き出す (**1枚ずつ `remotion still` を呼ばないこと。1回のビルドで【N】枚出せます**):
   ```
   node_modules/.bin/remotion render src/remotion/index.ts 【プレビュー合成名】 tmp/koso/【置き場】 --sequence --frames=【C1】-【C2】 --image-format=png --log=error
   ```
   出てくるのは `tmp/koso/【置き場】/element-【C1】.png` 〜 `element-【C2】.png`。**element-N の N に 【基準番号】 を足した数が文番号**です (element-【C1】 = 文#【A】, element-【C2】 = 文#【B】)
7. 【N】枚を Read して自分で検品する。見るところ: 主役が小さすぎないか / 物が重なって読めなくなっていないか / 画面の下1/4に大事なものを置いていないか / 人の手足や物のつながりが変でないか / 真ん中にポツンと置いていないか
8. 直して、もう1回だけ書き出して確認する
9. 終わったら、【N】枚それぞれを1行で説明した報告を返す (400語以内)

## 親側 (指示を出す人) の注意

- **Remotion の `--sequence` は0詰めする。** 最大コマが46なら `element-00.png`。担当に伝える綴りを間違えると「ファイルがない」で詰まる。`koso-sheet.sh` は3通り探すようにしてある
- **担当を起こす前に `tsc --noEmit` を通しておく。** 死んだ担当が残した型エラーがあると、全員のビルドが落ちて時間を溶かす (第2章で実際に起きた: `<Bricks … width={0} …/>` の残骸)
- **骨組みの共通部品は「シーン本体」の仕切りコメントより上に置く。** ファイルを分割したとき、その上の部分が各ファイルにコピーされるので、分けたあとの担当も煉瓦壁・帽子などを無料で使える
- 4人同時で各 79k〜128k トークン、28〜98 ツール使用。全員 NG 0 で帰ってきた
- **章の設計書には2つの表を必ず書く** (★2026-11-04)。`npm run check` の検査6 がこれを読んで格の配分を見るので、どちらが欠けても検査が空ぶりする
