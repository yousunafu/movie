# 第5章・第6章 第1回修正 — 共通ブリーフ

作者が完成動画を通し見して出した指摘を直す。**作り直しではなく、指摘された点だけを直す。**
指摘されていない部分の絵は、線・色・密度・動きをそのまま保つこと。

## 絶対ルール

1. **絵のクオリティを下げない。** 作者の明言:「細かい作りこんだ絵が生きるのは、そのバランスがあってこそ」。
   「シンプルに」という指摘は「要素を減らせ」であって「雑に描け」ではない。残した物はむしろ**大きく・中央に**置く。
   「小さい物を真ん中にポツンと」が最悪の失敗。
2. **コンポーネントの `seed` 番号を変えない。** `<Frame f={f} seed={NNN}>` の数字は今のまま。
3. **motif 名・コンポーネント名・export の形を変えない。** 置き換えるのは関数の中身だけ。
4. **自分の担当ファイル以外を書き換えない。** 読むのは自由。
   他のエージェントが同時に別ファイルを直しているので、はみ出すと衝突する。
5. **共通部品を勝手に増やさない。** `KosoShared.tsx` / `KosoB2Parts.tsx` / `KarakuriScenes.tsx` は**読むだけ**。
   そのシーン専用の物はそのファイルの中に書く。

## ★この作風での「手」の描き方 (重要)

この作品の人物は `Person` という部品で描かれていて、**手は白い丸いミトン**(指は描き分けない)。
肌色のリアルな手・指の関節線・爪は**この作風では異物**。作者から名指しで指摘が出ている。
大きな手を描くときも、

- 塗りは `KRP.white` (白)。肌色 (`#F0D0B8` のような色) を使わない
- 輪郭は `KRP.ink` で `strokeWidth` 6〜8 の均一な太さ
- 指は出しても**3本まで・丸い太い棒**。関節のしわ・爪・手相の線は描かない
- 袖口は服の色のリング1本で締める

という形にする。既にある良い例: `KosoB2b.tsx` の #100 (ボタンを押す手)。迷ったらこれを見る。

## 画面と座標

- 画面は 1920 × 1080。
- 絵の要素は **x = 60〜1860 / y = 200〜870** の内側に収める。
- 画面上部 y < 190 はタイトル帯 (「高層ビルのからくり」) の領域。ここに絵を置かない。
- **字幕帯**: 画面下に字幕が別レイヤーで出る。`TagPlate` の下端 = `y + size*0.85` が **830 以下**になるようにする。
  絵の中のテロップは y ≤ 780 に置くのが安全。
- 絵の中の文字は **ラベル・数値・標識だけ**。台本の文章を絵の中に書かない (字幕と二重になる)。
- 絵の中の文字サイズは **23px 以上**。

## 動き

- コンポーネントは `f` (0〜45程度) を受け取る。**必ず `f` で何かが動くこと**。静止画にしない。
- `seg(f, a, b)` で 0→1 の立ち上がりを作る。**`b` は 42 以下**にする (プレビューは f=45 で描かれるため、
  42 を超えると確認用の静止画に出てこない)。
- 札 (`TagPlate`) は `t={seg(f, a, b)}` で出す。
- カメラを寄せる演出は `zoomAt(z, cx, cy)` (KosoB2Parts) を `<g transform={...}>` に使う。
  例: `const z = lerp(1, 1.35, easeOut(seg(f, 6, 36)));` → `<g transform={zoomAt(z, 760, 560)}>`

## 絵の「格」(行数の目安)

- 山 = 舞台・人・事件・カメラ全部入り (150〜250行)
- 並 = 舞台はあるが主役は1つ。人は1人、背景3〜4要素 (60〜120行)
- 図 = クリーム地に図と札だけ。人も背景も置かない (25〜50行)

今の格を変えない。山のシーンを図に格下げしない。

## 色の語彙 (この作品で既に決まっている意味)

- 茶 `#9A6448` / `C.brick` = 煉瓦の壁
- 緑 `KRP.green` = 貸せる床・良いもの
- 赤 `KRP.red` = 失う分・できない印・危険
- 赤い破線 = 「本来ならここまでだったはず」
- 真鍮 `BP.brass*` = エレベーターの内装
- 鋼 `BP.steel*` = 機械・鉄骨

## 作業の進め方

1. 担当ファイルの、担当コンポーネントだけを読む (ファイル全部を読まなくてよい)。
2. 指摘された点だけを直す。
3. `node_modules/.bin/tsc --noEmit -p .` を通す。
4. **自分で絵を描き出して目で確かめる。** 自己申告は信用されない。
   ```
   npx remotion render src/remotion/index.ts KosoAll <出力ディレクトリ> \
     --sequence --frames=<F>-<F> --image-format=png --log=error
   ```
   `KosoAll` は **frame = 文番号 − 1**。出力は `<出力ディレクトリ>/element-NN.png`
   (ゼロ埋めの桁数は指定したフレーム番号の最大値で変わる。`ls` で実際の名前を確かめる)。
   出力ディレクトリは `tmp/koso/` の下に自分専用の名前で作る (他のエージェントと衝突しないように)。
   描き出した png を Read ツールで**実際に見て**、指摘が直っているか・絵が壊れていないかを確認する。
   細部は `ffmpeg -y -loglevel error -i <png> -vf "crop=W:H:X:Y,scale=880:-1" <出力>.png` で拡大して見る。
   直っていなければ直して描き直す。**見ずに「できました」と報告しない。**
5. `npx tsx scripts/koso-plate-check.ts <自分のファイルの接頭辞 例 KosoB5>` を通す
   (札が字幕帯に被っていないかの機械チェック)。
   自分が触ったシーンが NG に出たら直す。他のシーンの NG は放置してよい。
