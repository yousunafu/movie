## 絶対に守ること

1. **1文 = 1シーン = 1枚の絵。** 20文だから20枚。増やさない減らさない
2. **札 (TagPlate) の y + size*0.85 を 830 以下にする。** 画面の下には字幕の黒帯 (上端854) が別レイヤーで乗ります。検品プレビューには字幕が出ないので、目で見ても気づけません。必ず計算で守ること。検査スクリプトもあります (進め方の手順5)
3. **絵の中の文字は、ラベル・数値・標識だけ。** 台本の文章をそのまま絵に書かない (字幕が別に出るので二重になる)。札の文言は**字幕の言い換え**にする (字幕と同じ文言の札は禁止)
4. **必ず `f` で何かが動く。** 静止した絵は禁止
5. **出そろうのは f=42 まで。** 検品プレビューは全シーンを f=45 の瞬間で描きます。`seg(f, a, b)` の b は 42 以下にすること
6. 色は `KRP` と、ファイル上部の `C` にある色だけを使う。新しい色が要るなら `C` に足す (勝手な即値 #xxxxxx をシーン内に散らさない)
7. seed は 900〜919 を1シーンに1つずつ (もう骨組みに書いてあります。変えない)
8. 対応表 `SCENES` のキーと `I_B0_MOTIFS` は**変えない**。motif 名も並び順も変えない。Preview と dispatcher も変えない
9. **連番ペア (#4と#5 / #9と#10 / #19と#20) は絵を複製しない。** 1つのローカル部品に `phase?: 1 | 2` の prop を持たせて、同じ座標・同じ形のまま「何が増えるか」だけ変える。コピペで2個作ると後で形がズレて検品で差し戻しになります

### ★「図」「並」も品質は落とさない (作者の指示そのまま)

> 「シンプルとか普通のやつも絵のクオリティは下げちゃだめなんだけどね。だけど、細かい作りこんだ絵が生きるのは、そのバランスがあってこそなんだよね」

短いのは**賑やかさを削ったから**であって、雑に描いたからではありません。

- 線・色・札・フォントは山と**完全に同じ**。`strokeWidth` を細くしない。ゆらぎフィルタ (`Frame`) を外さない
- **必ず動く。** 静止した図は禁止
- **図そのものを作り込む。** 石板なら欠け・刻み線・台座まで。メダルなら縁の二重線・リボン・光まで。年表なら軸・目盛り・数字まで
- **大きく置いて画面を使い切る。** 最悪の失敗は「小さい物を画面の真ん中にポツンと置く」。シンプル＝**1つを、大きく、正確に**。主役の装置は短辺で画面の1/2 (540px) 以上を使う
- 余白は「空っぽ」ではなく「寄り」。余白があるのは、そこに寄っているから

## 使える部品

`import` 行はもうファイルに書いてあります (`void` 行は未使用エラー避けなので、使い始めたら消してよい)。主なものの使い方:

**`IchiShared.tsx` から** (KosoShared の再輸出。必ずこちらから import)
- `<Frame f={f} seed={900} bg={KRP.cream}>…</Frame>` — 手描きのゆらぎ+バッジ+空気。全シーンの外枠。必ず使う。暗い絵は `dark` を付ける
- `<TagPlate x y text size t color fill />` — 木札。`t` は 0→1 で pop。幅 ≈ text.length*size+40。**下端 y+size*0.85 ≤ 830**
- `<QMark x y s t f />` `<XMark x y s t />` `<Arrow x y s rot t />` `<ChapterDoor …>` (序では使わない)
- `W`=1920 `H`=1080 `FONT`

**`KarakuriScenes` から**
- `<Person x y s ...>` — x,y は**足元**。頭のてっぺんは y - 292*s。grep して props (pose・color 等) を確認してから使う
- `seg(f, a, b)` → f が a〜b の間で 0→1 (範囲外は0か1) / `easeOut(t)` / `clamp01(x)` / `pop(t)`
- `Stamp` (判子風の演出。#3 の「0人」に) / `Bolt` (衝撃線)
- `KRP` — 共通の色 (ink, cream, white, red, green, orange, yellow, gray, grayDark …)

**`KosoB2Parts.tsx` から** (**使う前に該当箇所を Read して引数を確認すること**。import 行は自分で足す)
`lerp` `rnd` `zoomAt` `bobOf` / `GridPaper` (図の方眼下地。「図」の下地に使う) / `Maru` `MaruBatsu` / `ForceArrow` / `Balance`

この範囲で要る物のうち既存部品にないもの (石碑・彫像・竪琴・稲束・高床倉庫・メダル・表彰台・土俵の輪など) は、**自分のファイルの中にローカルな部品として書いてください** (共用ファイルには足さない)。同じ物が2回以上出るときは、ローカル部品に切り出すと形がそろって得です。

## 「図」の見本 (別の回の文#71。これと同じ作りこみ・同じ大きさで描く)

```tsx
const Kb2RopeKasshaHito: React.FC<{ f: number }> = ({ f }) => {
  const SX = 760, SY = 330, SR = 210;          // 綱車の中心と半径
  const LX = SX - SR * 0.82;                   // 荷台側
  const HX = SX + SR * 0.82;                   // 手側
  const pull = (Math.sin((f - 10) / 14) * 0.5 + 0.5) * easeOut(clamp01(seg(f, 4, 28)));
  const handY = 640 + pull * 130;
  const loadY = 790 - pull * 130;
  const rot = -pull * 44 + f * 0.6;
  return (
    <Frame f={f} seed={605} bg={KRP.cream}>
      <GridPaper />
      {/* 吊り元の梁。画面を端から端まで横切らせる */}
      <rect x={-20} y={66} width={W + 40} height={58} fill={BP.wood} stroke={KRP.ink} strokeWidth={7} />
      {/* ロープ: 荷台 → 綱車 → 手 … 部品の内部まで描く */}
      <ForceArrow x={HX + 118} y={handY + 70} len={230} rot={90} w={24}
        color={KRP.red} t={seg(f, 14, 30)} label="引く" labelSize={36} />
      <TagPlate x={1450} y={330} text="滑車" size={56} t={seg(f, 6, 20)} />

    </Frame>
  );
};
```

要点: **主役を大きく / 画面の端まで使う / 部品の内部まで描く / 矢印と札で意味を言う / 必ず f で動く**。

## 進め方

1. まず `src/remotion/karakuri/IchiB0.tsx` を Read して骨組みを把握する。次に `IchiShared.tsx` と `KosoShared.tsx` を Read する (最初に読むのはこの3つだけ)
2. 各シーンを書くとき、コンポーネントの頭に `// どこ: // 演出: // 動き:` のコメントを**先に書いてから**描く
3. **「山」(#6・#8・#12) から先に描く。** 序の背骨なので、ここが決まれば残りが決まります。そのあと連番の図 (#4/#5, #9/#10, #19/#20)、#15の土俵マップ、最後に並
4. 書けたら型チェック: `node_modules/.bin/tsc --noEmit`
5. 札の検査: `npx tsx scripts/koso-plate-check.ts IchiB0` — **NG 0件になるまで直す**
6. 静止画を書き出す (**1枚ずつ `remotion still` を呼ばないこと。1回のビルドで20枚出せます**):
   ```
   node_modules/.bin/remotion render src/remotion/index.ts IchiB0 tmp/ichiban/b0 --sequence --frames=0-19 --image-format=png --log=error
   ```
   出てくるのは `tmp/ichiban/b0/element-0.png` 〜 `element-19.png`。**element-N の N に 1 を足した数が文番号**です (element-0 = 文#1, element-19 = 文#20)
7. 20枚を Read して自分で検品する。見るところ: 主役が小さすぎないか / 物が重なって読めなくなっていないか / 画面の下1/4 (y>830) に大事なものを置いていないか / 人の手足や物のつながりが変でないか / 真ん中にポツンと置いていないか / 連番ペアがちゃんと同じ形・同じ座標か / TODO の文字が残っていないか
8. 直して、もう1回だけ書き出して確認する
9. 終わったら、20枚それぞれを1行で説明した報告を返す (400語以内)
